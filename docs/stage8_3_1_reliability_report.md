# Stage 8.3.1 · Modbus TCP ↔ RTU 网关可靠性

本轮使用 WSL2 Ubuntu 24.04 下的 Zephyr native_sim、真实回环 TCP 套接字与两条 PTY 之间的字节转发。复用 Stage 8.3 的 TCP、MBAP 和串口协议实现，仅修复四槽位同时占用时的 TCP 重连处理顺序。验收为测量工具分配独立工作区、端口和每客户端审计文件。

## 测试方法

- **TID**：四个连接各 100 笔，TID 为 1–100、101–200、201–300、301–400。按每客户端各自的请求序号同步发起，逐笔对照 TCP 响应 TID、Unit ID、功能码和独立线圈读回。用 Gateway 的接收、worker 发出与 TCP 发送日志交叉核对 slot / generation 和计数。预热和末尾读回使用独立 TID。
- **RTU 时间窗口**：测量从 relay 看见下行请求起，到隔离释放实际回复字节的 Host 单调时间。在 500 ms 两侧设置重复测试点；过期 A 应收到异常 0x0B，释放迟到 A 前先排队 B。A 和 B 读不同寄存器，响应数据分别为 17 和 600。另对照 Gateway 的隔离与重新初始化日志。稳定性边界是从 worker 开始起 1,000 ms 响应最大年龄加 250 ms 恢复裕度；所测范围内验证迟到数据不会串单。
- **TCP 流与恢复**：逐字节和随机分片、拆分 MBAP/PDU、粘包及有限长度检查；记录慢速半帧、FIN/RST、写半关闭和同 TID 的不同 Unit。真实请求突发验证队列拒绝码 0x06。客户端断开后检查相同 slot 不同 generation，随后验证从站和网关实际进程重启。超时写的发出日志、寄存器值和计数分别核对。
- **Stress / Endurance**：四个独立进程经 TCP 发送 FC01/02/03/04/05/06/0F/10，按自己的地址核对读回与最终 GPIO/配置寄存器/写次数；记录主站单调延迟和 Gateway 日志的采样队列深度。Endurance 每隔 60 秒采集资源，每隔 120 秒先等待一条实际下游回复，再保持约 120 ms 后释放。每个周期记录被保持的字节数。
- **资源与取消**：首尾在预热后、连接关闭后的等价空闲状态比较，运行中保留 PID、进程资源采样与转发线程活动。会话结束核查 Gateway、Slave、Worker、Relay、PTY 和工作区锁。全量原始数据保留于本机 `build/stage831/`。

## 发现与修复

首轮耐久在客户端 0 第 120 笔完成后首次重连处收到 TCP reset，重连后的第一笔请求未进入 worker；最近一次采样的 488 笔提交无 RTU 超时、队列拒绝或异常。随后在旧固件上做定向回归：占用四个槽位、暂停网关进程、关闭一个旧 TCP 连接并发起新连接，再恢复进程。旧版对新连接返回 reset，确认是同轮轮询的处理顺序。旧日志保留在本机构建工作区。

修复先处理本轮轮询发现的客户描述符事件并释放失效槽位，再从监听 socket 接收新连接。保留四槽位容量、generation 校验和 RTU 单 worker。定向回归检查新 TID 和另外三个连接的各自响应。修改未增加连接或写请求重试。 复验也修正了两个测量条件：资源基线在预热后采集；清理判断针对本轮 PTY 实例，其他测试重新占用同一路径编号时单独记为编号复用。首批失败日志仍保留。

## 复验命令

```bash
python3 scripts/accept_stage8_3_1.py --mode tid
python3 scripts/accept_stage8_3_1.py --mode quick
python3 scripts/accept_stage8_3_1.py --mode stress
python3 scripts/accept_stage8_3_1.py --mode endurance
```

端到端延迟来自 Host 单调时间，Gateway 内部的 RTU/队列时序使用独立的 Zephyr 仿真时钟。不会相减两种时钟来源，也不会把 PTY 字节时间当成物理串口波形。RTU 没有事务 ID，超时写入结果可能不确定。本轮不承诺任意延迟的帧重放隔离或 Exactly Once。

## TID、Quick 与 Stress 实测

| 检查 | 结果 |
| --- | --- |
| TID | PASS。独立 TID 和最终 Quick 均为四客户端各 100 笔，400 个唯一 TID，线圈、Unit ID、功能码、slot/generation 和响应匹配 |
| RTU 边界 | PASS，12/12。期限前 A 正常的实测释放点为 100.3, 440.1, 460.4, 460.1, 470.1 ms；期限后 A 返回 0x0B 的释放点为 538.9, 540.3, 540.2, 560.2, 700.2, 900.2, 980.2 ms。12 笔 B 均返回自己的 600 |
| TCP 流 | PASS，15/15。真实饱和返回 8 个 0x06，TID 617–624 保留。新连接正确接收自身响应，已断连客户端的排队请求未进入 RTU worker |
| 故障与重启 | PASS，100/100 随机恢复；从站和网关各实际重启一次，旧 TCP 连接失效，新连接回读正确 |
| Stress | PASS，10,000 笔混合事务，加 4 笔各客户端初始化；每客户端 2,500 笔混合事务。所有 worker 请求与 TCP 响应、Gateway 三阶段和真实串口 PTY 字节逐笔对应。10,008 对串口帧（含前置/收尾）都通过 CRC |
| 停止清理 | PASS。主动取消运行返回 143，Gateway、Slave 和 4 个 Worker 均退出，原 PTY 与验收锁释放 |

超时写入用例实际返回 0x0B，有且仅有一次发出记录。随后回读 HR1=47，成功写计数由 3 增至 4，说明在本用例中写入已经生效，不能据上游超时推断设备状态。满载重连用例在旧网关失败，修复后替换连接和另外三个原连接均返回正确结果。

压力吞吐 19.99 笔/秒，端到端延迟 p50=199.76 ms、p95=229.88 ms、p99=231.06 ms；采样请求队列峰值 2，RTU 最大并行 1。超时、异常、队列拒绝及 stale 均为 0。首尾均为 7 个 FD、7 个线程，空闲连接为 0。压力和耐久使用独立网关、端口和 PTY，在同一台 WSL 主机上运行，吞吐仅代表此次测试。

## 30 分钟耐久实测

四个独立客户端重叠运行 **1801.177 秒**，完成 **15,002 笔混合事务**，各客户端 3751, 3749, 3751, 3751 笔。期间分别重连 31, 31, 31, 31 次。共捕获并核对 15,010 对正常 RTU ADU（含启动配置与最终回读）。端到端吞吐 8.33 笔/秒，p50 79.69 ms、p95 86.63 ms、p99 108.99 ms、最大 393.16 ms。最大 RTU 并行 1，超时、异常、拒绝、stale 和串口帧错配均为 0。

执行 15 次实际下游响应暂停，分别截获 6–8 字节的回复并原样释放。从第一批回复字节到释放的延迟为 125.35–208.84 ms。停止客户端后核对完整保持寄存器、线圈及 GPIO 位图。资源共采样 33 次，分钟采样另加空闲首尾。

| Gateway 资源 | 预热后空闲 | 运行中最大观测值 | 收尾空闲 |
| --- | ---: | ---: | ---: |
| FD | 7 | 11 | 7 |
| 线程 | 7 | 7 | 7 |
| VmRSS（KiB） | 2,748 | 2,756 | 568 |
| VmHWM（KiB） | 2,748 | 2,756 | 2,556 |
| VmSize（KiB） | 184,328 | 184,328 | 184,328 |

FD 从空闲 7 随四客户端增加到 11，收尾回到 7，线程始终为 7。VmSize 未变化。VmRSS 在前 25 分钟的在载采样为 2,756 KiB，随后下降；同一 PID 的 VmHWM 报告值同期从 2,756 降至 2,556 KiB，原因未定位，保留原始采样。此轮未观测到资源累积增长。Gateway、Slave、客户端进程、relay、PTY 和锁均已释放。
