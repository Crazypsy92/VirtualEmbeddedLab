# Scheduling, framing and recovery

Maximum four client contexts. Each has a 1024-byte stream buffer, fd, generation and last activity. Validate protocol=0 and MBAP length 2..254 before helper conversion; this bound matches the configured 256-byte RTU frame. Collect partial headers/PDUs, repeatedly consume complete ADUs and retain trailing bytes. Partial frames expire after 1 second, idle connections after 20 seconds. The listening address is 127.0.0.1; port defaults to 15020 but acceptance selects a free unprivileged port at build time and records it. Send loops handle short writes with a 100-ms bound; failure closes that connection.

Queue capacity 16 plus one active RTU transaction. One worker calls the official modbus_raw_backend_txn once per dequeued job with a 500-ms timeout. Queue saturation immediately returns exception6 (Server Device Busy). Unconfigured Unit ID returns exception10 (Gateway Path Unavailable). Downstream errors return exception11 (Gateway Target Failed to Respond). Device exceptions are forwarded unchanged. Successful responses must match the original unit/function; CRC remains official Zephyr code.

Every job owns an ADU copy, slot/generation and timing markers. No worker retains a TCP fd or pointer to a freed client buffer. Main loop alone closes and sends sockets. Atomic live-generation tokens reject queued work for disconnected clients; completion generation checks prevent responses reaching a recycled slot/fd. A bounded completion queue has 17 entries. Four independent client processes use disjoint TID ranges. Host and gateway logs verify preservation and no cross-client response delivery. Successful RTU transactions are serialized; the active peak is measured, not inferred from fixed output.

TCP delivery and serial execution are distinct. Disconnect may cancel a queued job, but an already dispatched write can execute after the master leaves. There are no hidden retries and no Exactly Once claim. A timed-out write is explicitly logged as issued with uncertain outcome. Generic RTU cannot distinguish a very late valid reply from another identical request: arbitrary delayed-frame replay is not solved by transaction IDs, because serial frames have none. Qualified fault restoration detaches/reopens the relay (discarding stale pending bytes) or restarts the affected process; unlimited delayed RTU replies are outside the proven recovery envelope.

Gateway stage markers use Zephyr uptime ms: TCP complete-ADU receive, official RTU API dispatch, API return and TCP send completion. Master times use Host monotonic seconds. Relay files additionally timestamp actual byte chunks in Host monotonic time. These are software/API/byte-channel measurements; do not subtract different clock origins or claim first-byte electrical timing. Queue and RTU API durations use one gateway clock; end-to-end percentiles use one Host clock.
