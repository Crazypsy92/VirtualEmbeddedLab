# Zephyr 4.4.2 Modbus compatibility

Audited the fixed local checkout (commit dccb09599635bdff17633fa7e9dab014b91dce90), subsys/modbus, include/zephyr/modbus/modbus.h, the rtu_server sample and zephyr,modbus-serial binding. Minimal official Server boot and real pymodbus FC03 transaction returned [123,123]. Compatibility PASS is based on that actual PTY exchange, not headers alone.

Official APIs: modbus_iface_get_by_name, modbus_init_server, modbus_iface_param (RTU/unit1/115200/even), modbus_user_callbacks for coil, discrete input, input and holding registers. Official serial path uses UART IRQ APIs, CRC16 ANSI with Modbus initialization and frame timers. FC01/02/03/04/05/06/0F/10 dispatch and serialization are the existing implementation. Client APIs exist but the independent master uses pymodbus 3.11.4, pyserial 3.5. TCP/raw ADU APIs were inspected only and are not implemented here.

Kconfig: MODBUS, MODBUS_ROLE_SERVER, GPIO, SERIAL, UART_INTERRUPT_DRIVEN, no floating point extension, buffer 256; serial child under uart1 uses zephyr,modbus-serial and DE/RE GPIOs. native_sim/native/64 produces Linux ELF. UART_USE_RUNTIME_CONFIGURE=n is necessary: native PTY lacks configure/config_get hooks. The requested software setting is 115200 8E1; actual PTY termios even parity returned EINVAL, so Host opens the byte channel without parity. No baud/parity/electrical timing validation is claimed. Official framing timeout at this configuration is 1002 microseconds simulated time. No third-party source was changed.

Important upstream API limitation: multi-write callbacks apply each item sequentially, allowing a late invalid address to leave earlier writes. Also callback errors map to illegal-address responses. A small application validation shim uses GNU --wrap=modbus_server_handler and the pinned internal modbus_context header to validate whole write ranges, lengths and application values before the original dispatcher. Rejected application writes return exception 2/3 through the same official RTU serializer. Valid requests always call the original dispatcher. This is explicitly a private-API integration tied to this exact Zephyr commit, not a portable public API claim; upgrades require renewed audit. It does not replace UART framing, CRC, standard successful function handlers or register callback implementation. Raw ADU/custom protocol replacement was not used.

The original DE/RE implementation drives GPIO before TX and returns to RX when uart_irq_tx_complete reports completion. native PTY reports immediate software completion. GPIO callbacks observe actual output state; no physical RS485 timing or collision behavior is modeled.

Timing limitation: native_sim runs at 100 Hz. The requested 1002-us RTU timer is quantized by Zephyr timer ticks and Host scheduling. Fragment tests use sub-tick gaps and recovery tests use explicit long gaps; no strict physical RTU inter-character timing compliance is claimed.
